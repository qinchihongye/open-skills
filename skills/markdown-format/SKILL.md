# markdown-format

为普通 Markdown 文档应用统一的固定排版风格。本风格不是 CommonMark 或 GitHub Markdown
的通行规范，也不用于编写 Agent Skill。以用户要求、项目规范和指定模板为最高优先级；
其余情况遵守本文件的硬规则。

## 0. 门禁（先执行）

1. 用户给出项目规范、模板或明确格式要求时，优先执行用户要求。
2. 创建、修改或审查 Agent Skill 及其配套文档时，停止使用本 skill。
3. 文件位于下列位置，或可由 `SKILL.md`、`agents/openai.yaml` 等结构确认属于
   Agent Skill 包时，默认停止使用：
   - `~/.codex/skills/**`、`.codex/skills/**`
   - `~/.grok/skills/**`、`.grok/skills/**`
   - `~/.claude/skills/**`、`.claude/skills/**`
   - 其它可确认的 `**/skills/<skill-name>/**`
4. 唯一例外：用户显式指定 `markdown-format`、`/markdown-format` 或
   `$markdown-format`，并点名一个具体 `.md` 文件。此时只处理该文件。
5. 只要求整理整个 skills 目录，或由 create-skill 流程自动生成 `SKILL.md`，不构成例外。
6. 门禁通过后，对普通 `.md` 文档使用本 skill。

同一对话中分别判断任务：Agent Skill 工作不使用；普通 Markdown 文档工作使用。

## 1. 模式分流

| 模式 | 时机 | 规则 |
|------|------|------|
| **A 修改** | 已有 md：整理/规范/格式化/检查 | **只改格式，绝不改内容** |
| **B 新建** | 新建 md、生成文档、整理成新文件 | **全文按规则写**（含标题/`*` 克制） |

默认：

- 已有文件 + 整理/改一下 → **A**  
- 仅改格式 → **A**  
- 新建/写一篇/生成 md（无已有路径）→ **B**
- 已有文件但要扩写内容 → 内容听用户；**格式仍须合规**

### 模式 A（铁律）

**允许：** 标题下补顶格 `*`；无序 `-`→`*`；调整缩进；补充能够确定的围栏语言标签；
将代码、表格、公式、图片和引用挂回所属 `*`；修复能够确定属于排版错误的围栏与分隔线。

**禁止：**

- 润色、改写、增删事实或调整正文语序
- 改动标题文字，或为了减少标题而合并、删除章节
- 改动 YAML frontmatter 的键和值
- 改动链接地址、图片地址、HTML 内容
- 改动代码块、Mermaid、公式、表格中的实际内容或数据
- 把 YAML frontmatter 的 `---` 当作普通分隔线处理
- 擅自删除口语表达、重复内容或最终代码

执行最小手术并保留原句。优先在裸段前补 `* `，不要借格式化解决内容问题。
完成后只说明格式改动点。

### 模式 B

按 §2–§3 生成完整文档；少标题、厚内容。

## 2. 硬性格式规则

### 2.1 标题后起笔

有正文的标题下，**第一条必须是顶格 `*`**。

标题下禁止直接：裸段、裸编号、裸围栏（含 mermaid）、裸 `$$`、裸表、裸图、裸 `>`。

仅允许例外：

1. 紧接下一级标题（中间无正文）  
2. 仅 `---`  
3. 文首第一个 `#` **之前**的 `[toc]`  

编号/代码/公式/表/图/引用 → 挂在某个 `*` 下。

此规则优先于“少用 `*`”：标题后的首个正文块必须属于顶格 `*`；同一主题的后续内容
尽量继续挂载在已有分类下，不要为每个段落新建 `*`。

### 2.2 标题（B 硬性；A 不重组目录）

- 最多三级：`#` / `##` / `###`，**禁止 `####`+**  
- **尽量少标题**；更深分类用 `*`  
- 一文多个 `#` 可以，但数量克制  
- 可选 `[toc]` 仅在第一个 `#` 前  
- 中文标题 + 英文专有名词  
- **默认不在标题里写章节序号**（如 `1.`、`1.1`、`3.1`、`4.2.1`）  
  - 多数 Markdown 编辑器、大纲与导出 PDF 会自动编号；标题再写序号会出现  
    `1.1 1. 版本记录`、`1.3.1 3.1 基础信息` 这类双重编号  
  - 标题只写语义名：`## 版本记录`、`### 基础信息`  
  - 需要引用「第 x 节」时写在正文 `*` 内，不写进标题  
  - **仅当用户明确要求**标题带序号时，才在标题文字中写入序号  

模式 A：**不为克制标题而并节/删标题**（除非用户明确要求精简层级且保留全部原文）。  
模式 A 默认**不删、不改**原文标题里已有的序号；用户明确要求「去掉标题序号」时再去掉。
### 2.3 列表

- 无序只用 `*`（任务列表除外可用 `- [ ]`）  
- `*` = 分类桶：**少而完整**；只做**一层**分类  
- **禁止** `*` 下再套无序 `*`（不要出现实心圆套空心圆那种层级）  
- 平级 vs 从属（先判断关系再排版）：

  | 关系 | 写法 |
  |------|------|
  | **平级**（并列分类，互不从属） | 拆成**多个顶格** `*` |
  | **从属**（同属某一分类下的说明/表/写法） | 全部挂在**同一个**顶格 `*` 下 |

- **从属**内容只允许这些挂载方式（均缩进在该 `*` 下，不再开新 `*`）：
  1. 段落（可多段连续写）  
  2. 有序编号 `1. 2. 3.`（步骤、多写法对比时优先）  
  3. 代码围栏 / 表 / 公式 / 图 / 引用  
- 禁止一句一条刷 `*`  
- 导语按需：`* 代码` / `* 相关解释` / `* 主流程` 等，不必每段都套  

### 2.4 代码 / mermaid

- 先 `*` 导语再围栏；围栏相对 `*` 缩进  
- 必须语言标签；未知用 `text`  
- 节后可用 `---`  

### 2.5 链接 / 图 / 公式 / 表

- 重要资料双写：`[text](url)` + 缩进 `>url`  
- 图挂步骤 `*` 下  
- 行内 `$...$`，行外 `$$...$$` 挂 `*` 下；话→式→其中  
- 表挂 `*` 下；表头+分隔行齐全  

### 2.6 可选（默认不用）

任务列表、脚注、HTML：仅渲染器需要时。强调优先 `**加粗**` 与行内代码。

### 2.7 语气（模式 B）

中文为主；标识符行内代码；简洁直述即可。

## 3. 骨架选型（模式 B，按需选用）

少标题即可，不必套满每一节。

- **算法/原理：** 主题 → 介绍 → 公式 → 代码 → 解释 → 示例  
- **教程/实操：** 摘要 → 环境 → 实现 → 使用 → 可选最终代码  
- **业务/混合：** 少量 `##` + `*` 分类（数据、口径、输出、流程等）  
- **其它文档：** 同样遵守 §2；按内容自拟少量标题，用 `*` 分类承载细节

按需读取引用，不要一次性加载全部：

- 模式 B 需要起稿骨架时，读取 `references/skeletons.md`
- 拿不准标题后起笔方式或模式 A 边界时，读取 `references/do-dont.md`
- 需要代码、Mermaid、链接、图片、公式或表格的标准形状时，读取
  `references/elements.md`

## 4. 工作流

1. 门禁 §0  
2. 模式 A/B §1  
3. B：少标题大纲 → 顶格 `*` 填内容；A：只做格式手术  
4. 自检：  
   - [ ] 门禁通过（非 Agent Skill 包，或已显式指定单个文件）
   - [ ] 已优先遵守用户要求、项目规范和指定模板
   - [ ] 模式正确  
   - [ ] A：所有受保护内容和值均未改变
   - [ ] 有正文的标题下第一条为顶格 `*`  
   - [ ] 无裸段/编号/围栏/表/`$$`/`>`  
   - [ ] B：无 `####`+；标题少；`*` 少而完整  
   - [ ] B：标题无手写章节序号（除非用户明确要求带序号）  
   - [ ] 无 `*` 嵌套 `*`；平级拆顶格 `*`，从属用段落/编号挂同一 `*`  
   - [ ] 围栏有语言标签；表在 `*` 下  
5. 勿把本 skill 原文抄进用户文档

## 5. 输出

- **A：** 只交格式修复 + 简短格式说明  
- **B：** 完整合规文档
- 用户明确例外时从其例外（A 默认仍只格式，除非允许改内容）
