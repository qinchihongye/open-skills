# HTTP API 文档生成

## 资源

- `assets/http-api-doc-template.md`：正式文档骨架。套用后只保留与接口相关的章节。
- `references/template-guide.md`：事实来源、字段填写、可选章节和交付规则。仅供 agent 阅读。

## 工作流

1. 确认项目路径、目标接口（名称或 path）和输出路径。用户未指定输出路径时，写入项目内合理的业务文档目录。
2. 确认可靠事实来源。默认按“用户明确指定的契约 → OpenAPI/协议 → 运行代码与模型 → 调用方代码和测试 → 旧文档”的优先级核对；用户指定唯一真源时遵从该声明。
3. 按“路由/注册 → Handler/Controller → 请求模型 → 响应模型 → 错误处理与下游依赖 → 配置”的顺序阅读代码。
4. 读取模板和使用说明，抽取 path、method、Content-Type、请求/响应字段、结构树、嵌套关系、鉴权、错误码、环境或服务信息。
5. 复制模板到业务路径，替换占位符；删除无关的可选章节，不要把 `references/template-guide.md` 写入正式文档。
6. 对齐输入/输出结构树、字段说明、请求/响应示例和错误码；区分 HTTP 状态码与响应体业务码。
7. 自检文档结构、字段一致性、占位符、secret 和输出位置，完成后交付文档并简述事实依据、待补充项和已删除章节。

## 硬性规则

- 项目、目标接口或实质性依据缺失时，只询问缺口，不交空模板冒充实档。
- 字段名、类型、必填性、默认值和错误码必须能回溯到可靠来源；不能照搬其他接口或模板示例。
- 代码无法确认的负责人、联系人、环境地址等管理信息写“待补充”，不得臆造；这类信息不应阻塞技术文档生成。
- 不输出明文 secret、盐值、Token 密钥或凭据，只说明获取方式或配置位置。
- 不修改或写入本 skill 包、`~/.grok/skills`、`~/.claude/skills`、`~/.codex/skills`；正式文档必须落在业务项目路径。
- 纯 Markdown 排版修复交给 `markdown-format`；本 skill 负责接口事实和文档内容。

## 交付前检查

- [ ] 已确认项目、目标接口和事实来源
- [ ] 已读相关路由、处理器、请求/响应模型及错误处理
- [ ] 文档只保留适用章节，没有空壳可选段
- [ ] path、method、结构树、字段说明、示例和错误码彼此一致
- [ ] 未编造字段、错误码、URL、联系人或凭据
- [ ] 未写入 secret，且输出位于业务项目路径
