# 接口文档模板使用说明

本文只供 agent 参考，不得写入正式接口文档。正式文档骨架位于
`../assets/http-api-doc-template.md`。

## 事实来源

默认优先级如下：

1. 用户明确指定的唯一契约或协议
2. OpenAPI 等正式接口定义
3. 路由、Handler/Controller、请求响应模型和校验器
4. 错误处理、调用方代码、测试和配置
5. 项目内旧文档

以代码为真源时，只有能在代码或配置中核对的内容才能写成确定事实。用户明确要求以契约为准时，按用户声明执行，不因缺少实现代码而阻塞。

## 使用步骤

1. 复制 `../assets/http-api-doc-template.md` 到业务项目的文档目录。
2. 先填写版本记录、摘要、基础信息和接口路径。
3. 再填写请求方法、Content-Type、输入结构树、鉴权、输出结构树和错误码。
4. 用真实字段、结构树和取值替换占位符；请求/响应示例必须与结构树和字段说明一致。
5. 删除没有依据或不适用的章节：服务注册、嵌套字段说明、鉴权细则、业务错误码、调用方或依赖方明细等。
6. 完成自测命令和期望响应；无法从代码确认的管理信息写“待补充”。

## 填写规则

- 只记录本接口真实存在的字段，不要复制其他业务接口的字段清单。
- 是否必须、类型、默认值和校验约束以请求/响应模型、校验器或协议为准。
- 输入和输出结构树使用 `text` 代码块；对象使用树形缩进，列表字段在字段名后标记 `[]`。
- 输入存在明确的请求模型、Schema 或根对象名时，结构树根节点和字段路径使用该真实名称；没有明确名称时统一使用小写 `request`。顶层为列表时使用 `request[]`。
- 请求根名称必须在结构树和全部字段说明路径中保持一致，不要使用 Handler、函数名或自行编造名称。
- 输出存在明确的响应模型、Schema 或根对象名时，结构树根节点和字段路径使用该真实名称；没有明确名称时统一使用小写 `response`。顶层为列表时使用 `response[]`。
- 响应根名称必须在结构树和全部字段说明路径中保持一致，不要使用 Handler、函数名或自行编造名称。
- 字段说明块按真实结构重复使用，标题使用完整字段路径，不固定“一级字段”“二级字段”等层级名称。
- 嵌套对象和列表只在真实存在时展开字段说明；纯文本、Markdown 或简单数组不创建空的对象字段表。
- 不要默认使用 `code`、`msg`、`data` 作为响应协议；字段名、类型和成功含义按实际接口填写。
- 将 HTTP 状态码与响应体业务码分开记录；失败示例中的 code 必须能在错误码表中找到说明。
- 结构树、字段说明和对应的请求/响应示例必须表达同一份结构；若成功与失败响应结构不同，应分别定义或明确说明。
- 鉴权部分只保留接口真实使用的方式，删除其他示例。Bearer Token 和 API Key 应说明传递位置、格式、获取方式、有效期及刷新方式。
- 自定义签名应说明待签名字段、拼接顺序、分隔符、字符编码、摘要算法、输出编码以及时间戳或重放保护规则。
- 环境 URL、负责人、工号、调用方联系人等代码无法确认的内容写“待补充”，不编造。
- Token、盐值、密钥和凭据只写占位符、获取方式或配置位置，不写真实值；示例中的 `【token】`、`【api_key】`、`【secret】` 必须保持为脱敏占位符或替换为明确的虚构值。

## 章节裁剪

| 章节或内容 | 处理方式 |
| ---------- | -------- |
| 版本记录、摘要、基础信息、请求说明、响应说明 | 通常保留 |
| 接口概述下的信息块 | 使用单层 `*` 标签，不为基础信息、环境地址、服务注册信息、调用方信息、依赖方信息单独生成三级标题 |
| 环境地址 | 有可确认地址时填写；没有则标记“待补充” |
| 服务注册信息 | 无服务治理或注册中心依据时删除 |
| 调用方/依赖方明细 | 无法确认时写“待补充”或删除明细行 |
| 鉴权 / Token 规则 | 只保留真实使用的鉴权方式；无鉴权时写“无”，并删除 Token、API Key 和签名示例 |
| 输入/输出结构树 | 结构简单时保留根节点和直属字段；无结构化字段时按实际类型简化 |
| 嵌套字段说明 | 无嵌套结构时删除 |
| 业务错误码 | 无自定义业务码时删除 |
| 自测方案 | 有可执行请求时保留；否则说明缺少验证条件 |

## 文档形状

- 保持模板的章节顺序和表格结构，但不保留不适用的空壳章节。
- “接口概述”下的五个信息块使用列表标签和表格呈现，避免在目录中产生过细的三级标题。
- 输入和输出结构树使用同一套通用表达方式，不把示例中的业务模块名称或层级术语固化到模板。
- 主要内容块名称使用 `* **名称**`；同一内容块内的嵌套字段路径或示例名称使用缩进后的 `**名称**`，不重复添加 `*`。
- 摘要正文等实际内容保持普通文字，表格和代码示例不额外加粗。
- 标题默认不手写数字序号，除非用户明确要求。
- 标题下的导语使用单层 `*`；不要嵌套 `*`。
- fenced code block 必须带语言标签，如 `json`、`bash`。
- 正式文档中不得出现本文内容、模板使用说明或内部推理过程。
